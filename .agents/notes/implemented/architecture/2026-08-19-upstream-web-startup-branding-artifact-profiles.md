# Agent Note: Web readiness, official branding, and client artifact profiles

Status: implemented

English | [中文](2026-08-19-upstream-web-startup-branding-artifact-profiles.zh.md)

## Problem

The Web command printed its URL as soon as its own runtime activated, so a sibling Loader row could still fail after a supervisor or browser had received a URL. The browser shell also owned the official mark and wordmark directly, which prevented a deployment from replacing branding through the client extension model. Finally, Vite and dynamically loaded client bundles had no shared record proving which public build values produced the current artifacts.

## Decision

The Web runtime waits for Loader settlement before printing its URL or opening the default browser. `--no-open` disables the handoff, SSH launch suppresses it automatically, and launcher failures remain warnings while the server continues. The URL is scrubbed from child-environment state that is not needed by the operating-system opener.

Sidebar and blank-session hero brand positions are generic slots. `ui-brand-official` fills them only for the `official` client build profile, so the shared shells no longer own a deployment-specific brand occupant.

The root build wrapper resolves one exact `DSH_CLIENT_*` environment for Vite and tsdown. `build:official` selects the shipped official profile; every complete build records the public values and a deterministic digest of the Web and dynamic client artifacts. Release packing verifies that the record exists, matches the official profile, and still matches the artifact bytes.

## Alternatives considered

Opening from the CLI or the generic HTTP server was rejected because neither owns both the OS-assigned port and the complete Loader readiness point. Waiting for a terminal confirmation was rejected because it breaks supervised and desktop launches; `--no-open` is the explicit unattended opt-out. Keeping official branding in the shared shells was rejected because deployment-specific presentation belongs in a replaceable client slot occupant. Recording only Vite output was rejected because dynamic plugin bundles are independently loaded and must share the same public build values and integrity check.

## Consequences

Server-only and SSH Web launches no longer invoke a desktop opener. A failed opener cannot make the Web process fail. A custom deployment can replace the official brand row without editing generic shell components, while unbranded or non-official builds retain the shell fallbacks.

A partial library or frontend build does not refresh the record, and release consumers reject a missing or stale record. The build record is gitignored because it describes generated bytes and the source revision; it is not a source-controlled release input.
