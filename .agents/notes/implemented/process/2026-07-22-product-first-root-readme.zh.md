# Agent Note: 产品优先的根 README

Status: implemented

[English](2026-07-22-product-first-root-readme.md) | 中文

## 问题

根 README 是仓库的产品入口和源码检出入口。它必须帮助新用户启动可用的 Web 会话，说明受支持的运行时界面，并将贡献者引导到各子系统负责的详细约定。产品能力、提供方配置、局域网服务、受管浏览器启动、工作区视图以及 SDK 入口都不应只能通过包 README 才能发现。

## 决策

根 README 采用产品优先的概览，随后提供可执行的安装路径、首次使用 Web 的步骤、局域网部署说明、Camofox 行为、其他入口模式、数据与隐私边界、定制入口和贡献者验证命令。英文和简体中文文件使用相同的技术结构，并保留可执行代码块的一致内容，使配对门禁能够验证它们。

页面将 Web 工作区作为主要界面来介绍：模型和凭据配置、工作区选择、会话创建、图片渲染、工作区文件浏览和 Git 提交历史。它也列出 headless、ACP、JSON-RPC 和 Python 界面，但不复制各自的详细参考。概览把随附的模型提供方选择、图片能力声明、会话事件日志权威性、SQLite 维护能力、权限、沙箱和遥测表述为部署事实，而不是实现状态。

Web 部署说明包含 `--host`、`--port` 和 `--trusted-host`，解释同一进程提供的回环与 LAN URL 如何共享会话，并说明未认证的 HTTP 服务器必须留在可信网络中，或置于已认证的 TLS 代理之后。Camofox 章节记录必需的浏览器下载、缓存刷新行为、受管的 `127.0.0.1:9377` 生命周期、截图展示、回环限制和外部可执行文件的退出路径。

README 链接到包、子系统、cookbook、CLI、用户、SDK、架构、配置目录和模块图参考，而不是复制完整 API 或实现约定。根页面负责产品导览、前置条件、可运行命令、安全警告和导航。

## 考虑过的替代方案

**保留短 README，只依赖包文档。** 这样会把主要用户流程、浏览器集成和部署警告隐藏在仓库导航之后。

**把根 README 变成完整的包目录。** 这样会让页面不适合作为产品入口，并重复自动生成的参考文档和包自身负责的约定。

**为中英文创建不同的结构。** 这会让两个入口表达不同的产品边界，并削弱仓库的双语配对约定。因此两侧镜像相同的技术大纲。

## 结果

当 Web 和 headless 命令、提供方配置、公开部署默认值、受管 Camofox 生命周期、主要用户流程或顶层产品界面变化时，必须更新根 README 及其中文对应文件。详细服务约定仍由各自文档负责。README 更新必须运行双语配对和文档门禁；命令或安全边界变化还必须更新归属参考文档。
