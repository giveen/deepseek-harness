# Agent Note：Camofox 浏览器活动面板

Status: implemented

[English](2026-08-19-camofox-browser-panel.md) | 中文

## 问题

Camofox 浏览器调用会提供可访问性文本和操作回执，但 Web 聊天没有显示 agent 正在检查的页面状态。

## 决策

每次成功的 camofox 操作都会尽力请求服务端截图接口，验证 PNG 响应，并在工具结果的展示元数据中最多保留 1.5 MB。操作的模型可见文本保持不变，因此截图不会消耗模型上下文，也不会改变工具工作流。元数据会进入持久化的工具结果事件，Host 在历史重放时重新计算工具结果视图仍可获得它。

客户端在与提供方无关的 Tool 展示词汇中注册 `browser` 结果视图。`ui-tool` 为五个 camofox 工具注册 keyed 行；有截图时自动打开有界的 `BrowserBlock` 面板。面板只把 Host 验证过的 `image/png` 字节放入 data URL，使用内部滚动的视口，并由详情 renderer 复用。截图捕获失败只会丢失可选展示；浏览器操作及其文字结果仍会正常结束。

## 考虑过的替代方案

**在 iframe 中嵌入实时页面。** 否决，因为这需要认证的页面代理或流式接口，会把浏览器状态暴露给第二个请求面，也无法从会话日志重放。

**把截图放入模型可见的结果内容。** 否决，因为需求是客户端视觉反馈而不是增加模型上下文；持久化展示元数据可以保持这一区分。

**创建独立的全局浏览器窗口。** 否决，因为 Web 客户端必须支持 LAN 会话，独立窗口会脱离聊天布局和 Host 授权模型。

## 后果

浏览器行会在每次成功操作后提供视觉跟随，同时保持模型行为和会话重放使用文本。过大、格式错误、不支持或不可用的截图不会阻塞浏览。面板是捕获的视图而不是实时控制面；交互仍通过模型可见的 camofox 工具执行。

## 测试

Camofox 工具测试覆盖截图捕获、PNG 元数据、快照查询参数，以及可选截图失败时的操作行为。ui-tool 集成测试验证 keyed browser 行分发、面板自动打开和截图 data URL。类型检查覆盖提供方无关的展示联合、UI 原子组件、camofox 包和工具 renderer。
